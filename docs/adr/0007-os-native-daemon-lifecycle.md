# OS-native socket activation on macOS/Linux, lazy CLI-triggered spawn on Windows

The daemon must start automatically on first use and not sit idle consuming resources, and must survive a crash without losing in-flight run state. On macOS (launchd) and Linux (systemd) we use OS-level socket activation: the OS starts the daemon on first connection, stops it when idle, and restarts it on crash, with in-flight state resumed from SQLite. Windows has no equivalent primitive in this scope, so the CLI instead checks daemon reachability and spawns it detached on every invocation if unreachable. This means the two platforms genuinely behave differently (Windows has no idle-shutdown or crash-restart guarantee) — accepted because Windows Service Triggers, which would close that gap, were out of scope for this round; the daemon's own logic doesn't depend on which mechanism started it, so the gap is isolated to lifecycle, not behavior.
