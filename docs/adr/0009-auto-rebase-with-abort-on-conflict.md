# Rebase stage auto-rebases and aborts on conflict, rather than just checking

The `rebase` stage rewrites the branch's history by running `git rebase` onto the detected base branch, rather than only checking whether the branch is behind and flagging it. This is deliberate: the rest of the pipeline (review, test, lint) should validate the branch as it will actually land once merged, not a stale version from whenever the branch was cut — a branch that passes validation against an old base but conflicts against the current one is a false pass. On a rebase conflict, the stage runs `git rebase --abort` to leave the repository clean and returns an `ask-user` finding rather than leaving a half-rebased working tree or guessing at a resolution — conflict resolution is a real decision only the human can make.
